# Заметки по проекту

## Что это
Практикум ПМ01 «Мини-магазин». Задание — 51.docx: в нём шаги только для лаб 0–2, для 3–8 —
только план и итоговая структура файлов. Лабы 3–8 сделаны по плану; когда придёт методичка,
сверить с ней (имена файлов, порты, команды).
- Этот репозиторий (`shop_pm01_home`) — готовый рабочий проект, делает Claude. Коммит + тег на лабу.
- `shop_pm01_full` — пользователь делает сам по шагам для преподавателя. Туда не пушить.

## Запуск
- Перед работой запустить Docker Desktop (без него `failed to connect to the docker API`).
- `docker compose up -d --build`, затем `docker compose ps`. С нуля ~1–2 мин.
- Замер: `docker compose run --rm k6 run /scripts/load.js`. k6/load.js не менять.
- Изменили db/init или нужна чистая база: `docker compose down -v` (init-скрипты идут только на пустой базе).

## Подводные камни (уже наступили)
- Git Bash превращает `/scripts/load.js`, `/sql/...` в `C:/Program Files/Git/...`:
  ставить `MSYS_NO_PATHCONV=1`. В PowerShell проблемы нет.
- nginx запоминает IP воркеров при старте → после пересоздания app был 502. Решено: `zone` + `resolve`
  + `resolver 127.0.0.11` (nginx ≥ 1.27.3). `zone` заодно сделал балансировку общей для всех процессов.
- PgBouncer кэширует DNS: после пересоздания реплик `shop_r2` ходил по старому IP в r1.
  Решено `dns_max_ttl = 2`.
- Остановленная реплика через PgBouncer давала ожидание до 30 с (DNS) → в `db.py` таймаут чтения
  с реплики 1 с и переключение на primary.
- Redis Cluster при failover: клиент ретраил до 10 с → потолок 0,3 с на операцию кэша.
- RabbitMQ: `rabbitmq-diagnostics` в healthcheck давал всплески CPU 150% каждые 10 с → `nc -z`.
  Плюс `+sbwt none` (busy-wait Erlang).
- asyncpg на каждый запрос слал RESET ALL/CLOSE ALL → `reset=_no_reset` в пулах.
- RPS во всех лабах ~240–290: потолок самого load.js (`sleep(0.1)`, ~30 VU). Прогресс видно по p95 и CPU.

## Решения
- Заказ: 202 + `pending`, оплату делает consumer; публикация после коммита, страховка — переотправка
  pending старше 5 минут.
- Индексы применяет одноразовый сервис `db-migrate` (db/sql/indexes.sql), а не init — чтобы
  в Лаб 7 был замер до/после.
- Edge кэширует только `/products*` и `/stats*` на 10 с; заказы не кэшируются.

## Не сделано
- Автоматический failover primary PostgreSQL (Patroni) — вне плана практикума.
- PgBouncer и edge — по одному экземпляру (единые точки отказа), отмечено в ответах.
