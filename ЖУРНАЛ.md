# Журнал замеров

Все замеры — `docker compose run --rm k6 run /scripts/load.js` (настройки по умолчанию, 50 VU, 70 с).
Полные отчёты k6 и `docker stats` — в папке `results/`.

Компьютер: 12 логических ядер, Docker выделено ~7,7 ГБ ОЗУ.

Почему RPS в Лаб 2 почти не вырос: k6/load.js даёт в среднем ~30 VU, и каждый ждёт `sleep(0.1)`
после запроса, поэтому тест физически не может дать больше ~245 RPS. Это предел клиента, а не сервера.
Разница видна по `docker stats`: в Лаб 1 app упирался в свои 0,5 ядра (50% CPU), в Лаб 2 каждый
воркер загружен на ~21%. Запас по производительности появился, но этот тест его не выбирает.

Опыт с отказом (Лаб 2, `docker compose stop app2` под нагрузкой): 0 ошибок из 16 774 запросов,
см. `results/lab2_failover_k6.txt`.
